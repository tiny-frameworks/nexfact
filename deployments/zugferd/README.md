## nexfact-zugferd
<sup>the *podman container zugferdmanager*, member of **GSF-nexfact ZUGFeRD** family.</sup>

---

This deployment provides a headless **Mustang-Project** Java runtime container designed for processing
hybrid ZUGFeRD / Factur-X e-invoices within the **GSF-NexFact** ecosystem.

It handles the automated injection of XML metadata into layout PDFs, performs standard validation, and extracts XML files or attachments.

---

## Core Capabilities

* **Generation:** Injects Factur-X/ZUGFeRD XML data into layout PDFs to build hybrid e-invoices.
* **Validation:** Validates hybrid PDFs and standalone XML files against official ZUGFeRD / Factur-X profiles.
* **Extraction:** Extracts embedded `factur-x.xml` files and additional attachments from existing hybrid documents.

## Components & Configuration

* **`nexfact/`**: A lightweight Java wrapper application that compiles into an executable Uber-JAR during
the container build process. It monitors the mounted input queue and handles atomic job execution.

### Supported Environment Variables

| Variable | Default | Description |
| --- | --- | --- |
| `NEXFACT_MODE` | `watch` | Execution mode (`watch` for continuous polling or `once` for single job execution) |
| `WATCH_DIR` | `/data/in` | Target directory inside the container monitored for incoming `job.json` files |

---

## Build & Run Instructions

The container expects the `zugferds` section of a tenant's `nexfact-env` directory structure to be mounted into `/data`.

### 1. Build Container Image

```bash
podman build -t nexfact-zugferd .

```

### 2. Run Container (Watcher Mode)

Execute this command from within the target tenant directory (e.g., `nexfact-env/sellers/default/`):

```bash
podman run -d --name nexfact-zfwatcher \
  -e NEXFACT_MODE=watch \
  -e WATCH_DIR=/data/in \
  -v ./data/zugferds/in:/data/in:Z \
  -v ./data/artefacts:/data/artefacts:Z,shared \
  -v ./data/zugferds/logs:/data/logs:Z \
  nexfact-zugferd

```

> **Note on Shared Artifacts (`:shared` flag):** The `./data/artefacts` volume is mounted as shared because the ZUGFeRD worker needs read access to the intermediate layout PDFs generated by the PDF worker (`nexfact-pdfmanager`).
